# 나의 취향 웹앱 — 설계 문서

- 날짜: 2026-08-21
- 작성자: Claude (jayunsu22@gmail.com 님과 브레인스토밍)

## 1. 목적 / 범위

"나의 여름노래 BEST5", "나의 드라마 BEST5"처럼 대분류-소분류-내용 구조로 개인 취향을 기록하는 개인용 웹앱.

- **공개 범위**: 본인만 보는 개인 기록용. 로그인 없이 URL만 알면 접근 가능(비공개지만 검색엔진 노출은 막음). 지금은 개인용으로 시작하되, 나중에 지인 공유로 확장할 수도 있음을 감안해 설계.
- **관리자 화면**: 비밀번호 보호 없이 URL로만 구분되는 가벼운 개인용 admin 페이지에서 직접 추가/수정.
- **이미지**: 파일 업로드 없이 이미지/유튜브 등 외부 URL만 입력.

## 4. Airtable 데이터 모델

새 베이스 **"나의취향"**, 테이블 2개.

### 4.1 `취향목록` (대분류-소분류 단위, 예: "여름노래 BEST5")

| 필드명 | 타입 | 설명 |
|---|---|---|
| 소분류명 | Single line text | 예: "여름노래 BEST5", "드라마 BEST5" |
| 대분류 | Single select | 예: 음악, 드라마/영화, 음식, 장소 … (admin에서 자유 추가) |
| 표시순서 | Number | 같은 대분류 안에서의 정렬 순서 |
| 항목 | Link to `취향항목` | 자동 연결 필드 |

### 4.2 `취향항목` (리스트 안의 개별 아이템, 예: BEST5의 1곡)

| 필드명 | 타입 | 설명 |
|---|---|---|
| 제목 | Single line text | 예: "여름밤에 - 잔나비" |
| 순위 | Number | 1~5 |
| 코멘트 | Long text | 왜 좋아하는지 한 줄 |
| 이미지/링크 | URL | 썸네일 이미지 또는 유튜브 등 외부 링크 |
| 소속목록 | Link to `취향목록` | 어느 소분류에 속하는지 |

### 4.3 정렬 규칙

대분류 그룹 → 그 안에서 `표시순서` 오름차순인 소분류들 → 각 소분류 안에서 `순위` 오름차순인 항목들.

## 5. N8N 백엔드 (웹훅)

기존 레일웨이 인스턴스에 워크플로우 1개, 웹훅 노드 4개.

| 웹훅 | 메서드 | 용도 |
|---|---|---|
| `/webhook/taste-get` | GET | 전체 취향목록+항목을 대분류별로 묶은 중첩 JSON 반환 (공개 페이지용, 이 API 하나만 호출) |
| `/webhook/taste-list-save` | POST | 소분류(취향목록) 추가/수정 — id 있으면 update, 없으면 create |
| `/webhook/taste-item-save` | POST | 항목(취향항목) 추가/수정 — 동일한 create-or-update 규칙 |
| `/webhook/taste-delete` | POST | 소분류 또는 항목 삭제. body: `{ type: "list" | "item", id }`. 소분류 삭제 시 하위 항목도 함께 삭제(admin에서 사전 확인 후 호출) |

- 인증 없음(개인용 결정과 동일). 웹훅 경로 접두어로 다른 프로젝트와 충돌 방지.
- 프론트 fetch는 레퍼런스와 동일하게 25초 타임아웃 래퍼 + 실패 시 토스트 에러 메시지 적용.

## 6. 프론트엔드

레퍼런스와 동일 구성: 프레임워크 없는 순수 HTML/CSS/JS 2세트.

### 6.1 `index.html` + `app.js` + `style.css` — 공개 조회 페이지

- 진입 시 `taste-get` 1회 호출 → 대분류별 섹션(예: "🎵 음악", "🎬 드라마/영화")으로 렌더링
- 각 대분류 안에 소분류 카드(예: "여름노래 BEST5") 나열, 카드 안에 순위순 항목(제목/코멘트/이미지 또는 링크)
- 이미지 URL이 유튜브 링크인지 일반 이미지 URL인지 간단 판별 후 각각 알맞게 표시
- 로딩 스피너 / 빈 상태("아직 등록된 취향이 없어요") / 에러 토스트

### 6.2 `admin.html` + `admin.js` + `admin_style.css` — 관리자 화면

- 비밀번호 보호 없음(URL만으로 구분되는 개인용)
- 대분류 선택(기존 값 드롭다운 + 새 대분류 직접입력) → 소분류 추가/수정 폼 + 표시순서
- 소분류 선택 후 항목 추가/수정 폼(제목/순위/코멘트/이미지링크), 기존 항목 리스트에서 수정·삭제
- 저장: `taste-list-save` / `taste-item-save`, 삭제: `taste-delete`

### 6.3 공통

- 캐시버스팅: `index.html`은 `app.js?v=YYYYMMDD`, `admin.html`은 `admin.js?v=YYYYMMDD` 방식. 해당 JS/CSS 수정 후 push할 때마다 `?v=` 값을 그날 날짜로 갱신.
- 반응형 레이아웃(모바일에서 admin으로 항목 추가하는 경우 고려).

## 7. 배포 (GitHub)

- 이 폴더(`D:\n8n_나의취향`)를 로컬 git 저장소 루트로 사용(초기화 완료).
- 배포 대상 파일(`index.html`, `app.js`, `style.css`, `admin.html`, `admin.js`, `admin_style.css`)만 추적하도록 `.gitignore` 구성.
- GitHub에 새 저장소 `my-taste`는 사용자가 github.com에서 빈 저장소로 직접 생성(Claude는 gh CLI/API 권한이 없어 저장소 생성 불가) → Claude가 로컬 remote 연결 후 `git push`로 반영.
- GitHub Pages를 저장소 루트에서 서빙하도록 설정 → `https://<계정>.github.io/my-taste/`.
- 이후 수정 시에도 항상 push 전 사용자 확인 후 Claude가 직접 push.

## 8. 향후 확장 여지 (지금 범위 아님)

- 지인 공유용 프로필형 페이지로 전환 가능성(디자인 강화, 공유 링크 등) — 지금은 개인 기록이 목적이므로 범위에서 제외.
